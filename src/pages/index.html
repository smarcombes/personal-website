I'm working on AI apps since before the ChatGPT era.

An agent isn't LLM + harness. It's LLM + harness + muscle memory — and that muscle memory shouldn't be Markdown. It should be executable software: skills an agent can run deterministically, evaluate against the real world, and improve on its own.

I don't make models. I build the software systems around them, so they can make a real difference for people in the field. Everything below is a piece of that: the skills themselves, the infrastructure that runs them, and the identity layer that lets them touch your services safely.

What I'm building now

Slices
2026 — now

A shadcn-compatible registry of fullstack features. One command installs the whole thing — the UI, the hooks, the API route, the access rules, the service behind them, and the resources they need. The code lands in your repo and stays yours: no runtime, no package to depend on, nothing left behind that says a registry was ever involved.

A table is never just a table. A table means a collection — which means auth, an audit trail, a database, and a route that filters what each user is allowed to see. Registries hand you the table and leave you the other five.

27 patterns across 6 families, each shipped for three component libraries, each backed by contracts you can swap without touching the UI. How it works →

ExtraOrbital
2026 — now

Cloud infrastructure that agents provision themselves. One command gives a project its databases, storage, queues and model keys, then writes the credentials back into the environment.

No console, no card, no human in the loop — which is precisely what makes the path agent-runnable end to end. It is the half that makes “fullstack feature” literal rather than aspirational. How it works →

BotParty
2025 — now

Agents forming teams to build entire companies from the ground up — the test field for removing humans from the loop entirely. Underneath it sits the part I care most about: around thirty services an agent can call directly, each with per-project keys, scoped permissions and its own ledger.

  • → coderun — a content-addressed cache in front of a sandbox. Install, typecheck, then compile down to an isolate, to Bun, or to Node, reporting exactly which step broke and where the code runs most cheaply. Agent-written code executes without anybody having to trust it first.
  • → multipass — delegated OAuth. Add “Connect with Google” to a project without ever registering credentials with Google, and verify email or phone without wiring a provider.
  • → the catalogue — Mongo, S3, Upstash, domains, VMs, mail, payments, model keys with per-project budgets. Delegable, expiring credentials throughout, so handing an agent access is never the same as handing it your account.

Interagentic
2025 — now

Dead simple auth for humans and agents. One integration covers both: people signing in, and the machines acting on their behalf. Agents get their own keypair identity and capabilities a human approves once — the successor to Keychains.dev, which let agents call any API in the world, fully audited, without ever touching the user's credentials.

How I got here

Creative Robots
2021 — now

I built my first vibe-coding product before ChatGPT, when models didn't reliably know how to emit valid JSON. It churned too much to trust, so I spent the two years after that on rail-coding: making AI generate large production applications deterministically, by composing reusable full-stack capabilities instead of re-deriving them.

Its main output is Layouts.dev — pure software that outputs complete Next.js and Expo projects from a simple DSL: intuitive enough for designers to use in place of Figma, and text-based enough for agents to edit directly. Slices is what I learned from it, distributed the way an open primitive should be rather than as a platform you have to join.
