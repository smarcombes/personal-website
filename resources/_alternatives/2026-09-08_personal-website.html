Agent-native software · 2021—2026

Building the environment for autonomous agents.

I've spent the last five years exploring how to move work out of the model and into the environment — so agents can do more with less inference, fewer errors, and increasingly reusable capabilities.

MODEL = intelligence
HARNESS = execution
ENVIRONMENT = leverage

My work lives mostly in the third line.
01 / Thesis

Models should reason about what's new. Everything they've already learned how to do should become software.

Every time a model reconstructs a solved procedure from scratch, we pay again in tokens, latency, cost and probability of error. I want successful reasoning to leave something durable behind.

The environment should progressively absorb that knowledge: better primitives, executable skills, composable artifacts, identity, credentials and infrastructure the agent can invoke directly.

Exploration 012021—2025

Better primitives

Reduce how much reasoning an agent needs to turn intent into working software.

Our software stack was designed for humans. It exposes enormous implementation surface area, creates endless valid-but-wrong choices, and forces models to burn inference on accidental complexity. I explored higher-level primitives that preserve control while making correct output easier to produce.

Layouts.dev → Slices.sh
UI primitives ↗
Composable interface primitives that let humans and agents describe product intent without rebuilding the implementation stack each time.
Railcoding
Constrained generation
A coding environment built around rails: known components, typed services and constrained building blocks that make generation faster and less error-prone.
Exploration 022025—2026

Compounding capabilities

Use the model once to figure something out. Turn what worked into a reusable primitive. Don't solve exactly the same problem twice.

Agents are extraordinarily wasteful when every task starts from a blank context window. I'm interested in systems where successful work becomes durable, executable and improvable — so capability accumulates outside the model weights.

Skills.dev → OpenIntegrations + MuscleMemory
Executable knowledge
Acquire knowledge through action, capture it as runnable/testable TypeScript, then share and improve it across agents. Built before Anthropic introduced Agent Skills; now being refactored and rebranded.
Open Widgets
Composable artifacts
Reusable interactive artifacts agents can invoke and compose instead of regenerating whole interfaces from scratch.
Exploration 032026—

Agent-native infrastructure

Remove the human from the control plane.

Accounts, API keys, dashboards, billing flows and cloud consoles all assume a human operator. Autonomous agents need infrastructure with different primitives: machine identity, bounded authority, programmatic provisioning and resources that can be acquired at runtime.

Interagentic
Agent identity
Identity and authorization primitives for agents that need to act without requiring a human account in the loop.
ExtraOrbital.dev
Provisioning ↗
Resources an agent can discover, provision, constrain and pay for programmatically — without a person opening a dashboard first.
03 / Direction

The model stays general. Its software body gets better every time it acts.

The end state I'm interested in is an agent environment that compounds: reasoning is reserved for novel work, while successful experience is progressively compiled into reliable capabilities.

04 / One trajectory
2021—2025

Make software easier for models to manipulate.

Reduce the surface area between intent and production code with agent-friendly primitives.

2025—2026

Make successful reasoning reusable.

Capture procedures and artifacts as executable, testable capabilities instead of paying to rediscover them.

2026—

Make the world directly operable by agents.

Identity, authority and resource provisioning without assuming a human is sitting behind the agent.
