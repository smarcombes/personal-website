ExtraOrbital

Cloud infrastructure that agents provision themselves. Databases, storage, queues and model keys in one command — no console, no card, no human in the loop.

By Séverin Marcombes · extraorbital.dev

Every automated pipeline I have built eventually stops in the same place. The agent writes the code, the code needs a database, and now a human has to open a dashboard, click through a provisioning wizard, copy a connection string, and paste it into an environment file. One manual step, and the whole loop is no longer a loop.

ExtraOrbital removes that step. It is a hosting provider whose primary user is a program: it gives a project its databases, storage, queues and model keys in one command, and writes the credentials back where the code expects to find them.

No console, no card, no human in the loop.

One command 

$ npx extraorbital provision .

  reading project…            4 resources declared
  ✓ mongo      cluster ready  → MONGODB_URI
  ✓ s3         bucket ready   → S3_BUCKET, S3_ACCESS_KEY_ID, S3_SECRET
  ✓ upstash    redis ready    → UPSTASH_REDIS_URL
  ✓ openrouter key issued     → OPENROUTER_API_KEY

  wrote .env.local

The project declares what it needs; ExtraOrbital creates the real thing on a free tier and hands back the variables. A human gets a working project in seconds. An agent gets something better: a step it can take on its own, without a credential it was never supposed to hold.

Identity turned out to be the hard part

The obvious design gives each user one downstream identity. That breaks the moment two people share a project, because one member's resources land in the other member's namespace. So a team sits between the user and the project: the hierarchy is user, then team, then project, then service. Every user owns a default team from their first request, so a single-player caller never has to learn that teams exist.

Machines get a first-class identity rather than a borrowed one. An agent carries its own Ed25519 keypair and a set of capabilities a human approved once, and both the protocol's execute endpoint and the plain REST API run through the same service layer and enforce the same grants. Delegating access to an agent is never the same act as handing it your account.

Money is the other hard part

Anything an agent can provision, an agent can provision a thousand times at four in the morning. So spend is a first- class object: a ledger per team and per project, budget caps that raise alerts before they bite, invoices, and team- scoped API keys that can be rotated without losing the limits attached to them.

This is the part people underestimate. Autonomy without a budget boundary is not autonomy, it is an incident waiting for a postmortem.

Why it pairs with Slices

A Slices feature declares the resources it depends on, and its accessor fails loudly with the exact command that fixes it. ExtraOrbital is the other half of that sentence — the reason a registry can promise a running feature rather than a compiling component.

Taken together they describe the shape I think agent infrastructure wants to be: capabilities that install as readable code, resources that provision themselves, and an identity layer that makes both safe to hand to a machine.
